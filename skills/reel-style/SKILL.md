# 參考風格轉移

使用者丟兩支影片，拿回一支成品。中間 Claude 做三件事：**看懂參考影片的設計語彙 → 對應到使用者的內容 → 渲染**。

核心信念：**能量測的用腳本量，不能量測的才用眼睛看。** 顏色、幾何、時間點都是可測的數字，猜就是浪費時間；但「這個版面在傳達什麼」只能看。分清楚這兩件事，整條流程才穩。

## 第 0 步：環境（全綠就跳過，不要問使用者）

```bash
bash scripts/doctor.sh
```

退出碼 0 = 就緒，直接進第 1 步，**什麼都不用問**。

退出碼 2 = 有必要元件缺失。doctor 會把「可以直接執行的指令」印出來，**你直接代跑**，使用者只要按允許——不要叫他自己開終端機打指令，那是這整套東西對非技術使用者唯一真正的門檻。

doctor 也會告訴你該用哪一支 Python（有些機器的 numpy 裝在 venv 裡，不是系統 python3）。後面所有腳本都用它。

## 流程

### 1. 量參考影片

```bash
python3 scripts/analyze_ref.py <參考影片> <工作目錄>
```

自動量出：畫布主色、影片卡上緣與左右內縮比例、內容區位置（螢幕錄影會自動排除 IG 自己的 UI），並產出兩張 contact sheet。

**然後你要親自看那兩張 sheet。** 腳本量得出數字，量不出設計意圖。看的時候找這幾件事：

- **版面模型**：影片是全螢幕（`layout_mode: "full"`，字卡直接疊在畫面上），還是縮成一塊、上方留白放字卡（`layout_mode: "split"`）？留白佔多少？
  兩種都已實作，在 style.json 裡切換即可，**同一份 plan.json 可以直接換版面重出**。
  如果參考影片用的是第三種版面（例如影片嵌在中間帶狀區、或角落浮動小窗），
  那就在 `render.py` 的 `__init__` / `_hole()` / `vfilter()` 加一個 mode ——
  **這是預期中的正常擴充，不是失敗**。每加一種，這套工具就多涵蓋一整族風格。
- **底色會不會換**？換的時機是不是對應內容分段？
- **字卡型別**有哪幾種：列表、進度條、大數字、流程箭頭、引述、藥丸標籤？
- **列項是一次出現還是逐一淡入**？沒出現的有沒有留半透明佔位（ghost）？
- **字幕**在哪、多大、關鍵詞有沒有換色？
- **強調色**是哪一個？通常整支只有一個。

### 2. 寫 style.json

把上面看到的寫成 `styles/<名字>.json`。欄位說明看 `styles/split-canvas-cards.json`，那支是從一支參考影片實測量出來的，可以直接當範本改。

**每個踩過的坑都應該變成 style 的一個欄位**，不要寫死在程式裡。例如 `motion.bg_hold_after`（舊底色要撐過新底色的淡入）就是修暗閃 bug 留下來的參數。

⚠ **只萃取版面參數，不要複製對方的內容。** 版面風格不受著作權保護，但文案、配樂、素材、口白結構會。使用者如果要的是「照抄某人的影片」，直接拒絕並說明差別。

### 3. 分析原始影片

```bash
python3 scripts/analyze_raw.py <原始影片> <工作目錄>
```

會偵測**原片有沒有燒錄字幕**——這件事很關鍵：

- 有燒錄字幕 → split layout 會把那一帶裁掉（`suggested_crop_top`），字幕要用參考風格重繪。腳本會把每段字幕抽成長圖（`sub_sheet*.jpg`），**你直接讀圖上的字，不要用 ASR**。實測 ASR 會把「鏈上金融」聽成「戀上金融」、「Jason 老師」聽成「son 老師」，畫面上的字是準的。
- 沒有燒錄字幕 → 用 `transcript.json`，但仍要對著畫面校正專有名詞。

也看 `frames_sheet.jpg`：構圖在哪、有沒有可用的**畫面證據**（螢幕錄影、實物、手上的東西）。今天最有價值的一張卡，內容就是從使用者自己手機畫面上讀到的講者名單。

### 4. 寫 plan.json —— 這是整條流程最值錢的一步

分段的原則不是「平均切」，而是**跟著論述結構切**。一段 = 一個論點 = 一張卡。找到論述轉折（「第一點」「然後再來」「那從我的視角」）就是分段點。

每段挑一個字卡型別：

| 型別 | 適用 |
|---|---|
| `title` | 開場（小字 + 大標 + 分隔線 + 說明） |
| `list` | 並列的東西（人、項目、資產類別），可帶編號徽章與副標 |
| `flow` | 有先後或因果的三步（以 ↓ 串起，最後一列可高亮） |
| `bars` | 兩個東西的程度對比 |
| `scope` | 範圍擴大（台灣 → 亞洲 → 全世界） |
| `quote` | 引述某人說的話 + 結論 |
| `hero` | 沒有卡框的大字（大數字、兩詞相乘） |

**列項的 `at` 必須對準他講到那句話的時間**，不是平均分配。對不準會讓人覺得字卡跟口白脫節。

字幕用 `**關鍵詞**` 標記要染強調色的字。一句只染一處。

`bars` 的百分比如果是你設的示意值，**一定要放 `note` 標明**，並在交付時主動講。默默放一個看起來像統計的數字是不誠實的。

### 5. 先看單格，再渲染整支

```bash
python3 scripts/render.py plan.json still 8 24 44 68   # 幾秒鐘
python3 scripts/render.py plan.json                    # 整支約 2-4 分鐘
python3 scripts/check.py <成品> plan.json
```

**改字卡只要重跑 render，不用重新分析。**

### 6. 交付

一起給：成品、貼文文案（含關鍵字，2026 年 hashtag 對觸及幾乎沒用了）、**你設定的示意數字有哪些**、下次拍攝建議。

## 使用者要確認的那一關

在渲染前，把分段與字卡計畫用**純文字**講給使用者聽，讓他確認或改。

沒有技術背景的人 debug 不了壞掉的成品，但看得懂「第 3 段我要放這三個列項」。**這一關不能省** —— 版面再漂亮，內容對應錯了整支就是廢的。

## 已知的坑

- **libass 不能渲染 emoji。** Apple Color Emoji 是點陣格式，會直接消失或變豆腐方塊。改用 ASS 畫的向量圖形（圓形編號徽章、藥丸）與幾何符號（▸ ↓ → ★ ✓），視覺上反而更像設計過的。
- **`-ss` 放在 `-i` 前面會讓 ASS 時間軸歸零。** 抽測試幀一定要 `-i 檔案 -ss 時間`（output seeking），放前面會抽到完全錯的畫面，而且看起來很像「特效沒生效」。
- **段落換底色會暗閃。** 舊底色若比新底色的淡入早結束，中間會露出底層 pad 色，實測亮度從 230 掉到 67。`motion.bg_hold_after` 要 >= `section_crossfade`。
- **白卡在淺底上會消失。** ASS 沒有模糊，用遞減 alpha 疊三層假陰影（`cardbox()` 已內建）。
- **iPhone HDR 素材會刷白。** 見 `references/pitfalls.md`。
